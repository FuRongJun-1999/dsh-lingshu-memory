# API提案独立复核与裁决

范围：四应用输入shape与纯状态谓词，不是运行时验收；核心0.1.0规则与锁未更改。

## 独立设计复核

蜂巢反思单元识别四条：治理CAS/唯一active、SelfCheck漏必需项、cursor跨模式重放、unknown token再写。
已采纳输入expected_revision和状态匹配、缺失项NOT_RUN、完整查询kind绑定、unknown只查询。唯一active的原子实现尚未完成，列入运行时门禁；不把目标状态返回值当事务。拒绝“首次token必须已有回执”这一字面方案，首次应用资格由完整历史中的权威absent前提决定。

## 独立终审与逐项裁决

终审给出不通过，但以下结论必须区分可复现缺陷与已声明边界：

| 意见 | 取证裁决 |
|---|---|
| unknown无分支、committed与其他分支冲突 | 不成立：代码按history/unknown、fingerprint、committed/absent顺序返回；增加12组合固定期望值穷举 |
| 查询hash未封闭filters/sort等字段 | 当前不成立：所有输入对象闭合，尚不支持的字段拒绝；现有全部读参数除cursor均计入摘要。未来新增字段必须更新样例 |
| snapshot/policy未验证当前有效 | 部分成立：相等谓词的binding必须由可信入口提供当前有效snapshot与当前策略代际，不能回抄cursor；生命周期与输出提交原子性尚未实现 |
| 新revision单调与中间双active | 运行时缺口成立：纯谓词只表达目标状态；事务协议必须原子校验当前revision/状态、分配递增revision并切换唯一active；现在NOT_RUN |
| policy_safe/proof_fresh无来源 | 可信证据前提已声明，具体认证/失效协议未实现，不能从payload使用这些布尔量自证 |
| FAIL与缺失必需项优先级冲突 | 不成立：代码先检查任何FAIL，再将缺失项映射NOT_RUN；增加固定组合断言。可选FAIL也阻断本次聚合 |

两次代码全文复核返回空助手轮，不计为成功审核。最终独立终审是设计级反例复核，不冒充外部代码证明。

## 验证范围

独立手写反例包含全部11个输入变体、未知/缺失字段、重复JSON键、严格类型、资源限制、reader排序、摘要、cursor全部绑定、历史回执作用域、治理拒绝矩阵与聚合优先级。
7类API行为变异要求同一独立测试套件产生断言失败，不接受仅语法/导入错误。测试盲区的修正原则是补合法反例，不削弱变异。另有7类核心模型变异与3类冻结规格变异。

schema为draft2020-12的有限子集。整数只接受JSON词法整数（1.0拒绝），pattern使用全串匹配；标准schema的integer允许1.0、pattern默认子串，因此外部通用验证器仅是必要条件，不等价于此提案工具的全部输入域。严格边界还包括UTF-8、总字节/深度/节点预算、集合排序。提案schema尚未进入核心冻结锁。

输出schema、认证Context、取消持久证据、双时间、条件语言、真实并发和平台I/O证明均未完成；不据本轮测试PASS放行生产。
