# 外部锚清单（External Anchors）

本文件说明：要把本仓库的阶段结论从 `I1` 抬到 `I2`/`I3`/`I4`，**各缺什么外部设施**、当前状态如何、以及在缺设施期间**明确不允许**做什么。

受 `scripts/ledger_check.py` 机检：文件必须存在、必须含 `## I2`/`## I3`/`## I4` 三节，且全文必须出现“当前状态”与“不允许”两个关键词（实际每节为三项：当前状态 / 所需设施 / 不允许）。

## 共同前提

阶段门的 `--trusted-key`、`--pin-manifest-sha256`、`--pin-requirements-sha256`、`--pin-ref-sha`、`--require-ref` 目前全部由**同一条命令行**给出。验证方与被验证方未分离，因此签名只能证明“某个密钥签了这段内容”，不能证明“另一方独立复核过”。

## I2（独立方在自己环境执行并核对提交字节）

- 当前状态：**缺失**。没有第二个环境执行记录；本仓库测试全部在同机串行跑。
- 所需设施：另一个执行环境（不同 OS 或容器）+ 执行回执（命令、退出码、树哈希、日志哈希）。
- 不允许：未取得该回执前，不得把任何 `PASS` 写成 `I2`，也不得在 PR 描述里声称“已被独立验证”。

## I3（带外信任根：注册表或 CI 侧签名）

- 当前状态：**部分具备**。RFC 8032 向量回归可在 CI 证明 Ed25519 实现与标准互通；但注册表与钉住值仍由提交方提供。
- 所需设施：带外注册表（门禁 id → 精确命令 + 最低独立性）与 CI 侧对 `(gate_id, command, exit_code, tree_sha, log_sha256)` 的签名回执。
- 不允许：不得把本地签名的 attestation 表述为“CI 已背书”，也不得据此变更 release gate。

## I4（不同时间、不同组件、不同主体的延迟复现）

- 当前状态：**缺失**。所有复核来自同一模型家族、同一会话时段、同一注入文本。
- 所需设施：时间上分离（≥2 个独立时段）、组件上分离（例如仅审文档 / 仅审密码学模块）、主体上分离（不同签署密钥）。
- 不允许：不得把单次复核的结论外推为“长期稳定”，也不得用“历史多次通过”替代延迟复现。

## 设施具备前后的行为约束

1. 设施缺失期间，`independence` 上限固定为 `I1`，由 `ledger_check.MAX_GRADE` 强制；
2. 需要提升上限时，必须**先**补齐对应设施并留下可复核回执，**再**修改 `MAX_GRADE` 并同步本文件；
3. 任何 production/power 放行、`M6` 迁移判定、release gate 变更，均要求 `I3` 及以上；在此之前一律 `BLOCK`。

## 与台账的关系

`docs/STAGE_LEDGER.md` 记录每个候选的等级与门禁值；本文件记录**为什么上限停在这里**。两者必须同时通过机检，任何一方缺失即门禁失败。
